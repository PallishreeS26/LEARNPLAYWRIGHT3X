# Source Code vs Byte Code vs Binary Code

## Breakdown Table

| Layer | What it is | Human-friendly? | Example | Main purpose |
|---|---|---|---|---|
| Source Code | The original human-written program | Yes | `hello.js` | Easy for programmers to read and write |
| Byte Code | A lower-level intermediate form generated by a compiler/interpreter | Partly | A compact instruction set inside the runtime | Faster execution than raw source code |
| Binary Code | Machine instructions executed directly by the CPU | No | `10110100 11001010 ...` | Actual execution on hardware |

## Simple Example Walkthrough

### 1) Source Code

File: `hello.js`

```javascript
function greet(name) {
    return "Hello, " + name;
}

console.log(greet("Ava"));
```

This is source code because it is written in a programming language that humans can read.

### 2) Byte Code

When the JavaScript engine runs this file, it may convert it into an intermediate form called byte code.

Example idea:

```text
LOAD_CONST "Hello, "
LOAD_VAR name
CONCAT
RETURN
```

This is not the original source code, but it is also not the final CPU instructions. It is a middle layer.

### 3) Binary Code

Finally, the computer processor needs machine instructions.

Example idea:

```text
10110100 00111001 11001010 00000001
```

This binary form is what the CPU can execute directly.

## Pipeline Diagram

```text
Source Code (.js)
        ↓
   Byte Code
        ↓
 Binary / Machine Code
        ↓
   CPU Execution
```
